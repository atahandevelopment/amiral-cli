# Lessons Learned

## SETUP-001 — Scaffold of apps/web (2026-08-16)

- `create-next-app@latest` installed **Next.js 16.3.1**, which has notable breaking changes vs. older training data: Turbopack is the default for `next dev` and `next build`; `next lint` is removed (ESLint CLI / flat config instead); `error.tsx` receives `error`/`retry` props (not `reset`); `images.domains` is deprecated (use `remotePatterns`); `next dev`/`next build` share a lockfile that blocks a second dev server on the same project. `create-next-app` also left a stale `next dev` process running after the scaffold — had to `taskkill` it before testing on another port.
- The bundled Next docs live in `node_modules/next/dist/docs/` and `AGENTS.md` points there; read them before writing code against Next 16.
- The shadcn CLI is now **v4.x** and its flags changed: `init` needs `-b radix --preset nova` to run non-interactively (older `--base-color` flag is gone). It generates components with the unified `radix-ui` package and expects a `--font-sans` CSS variable (create-next-app's `--font-geist-sans` does not match; use a system font stack instead).
- `@vitejs/plugin-react@6` requires Babel 8 and conflicts with shadcn's Babel 7 runtime deps (`ERESOLVE`). Pin `@vitejs/plugin-react@^5`.
- Vitest will happily pick up Playwright specs in `tests/`; scope Vitest to `src/**/*.test.{ts,tsx}`.
- Vite 7+ resolves `tsconfig` paths natively (`resolve.tsconfigPaths: true`) — `vite-tsconfig-paths` is no longer needed.
- Next 16 `tsconfig`/`next-env.d.ts` reference generated types in `.next/`; avoiding the generated `LayoutProps` helper (use plain `{ children: ReactNode }`) keeps `npm run typecheck` working on a fresh clone before `next dev`/`next build` has generated them.

## SCA-003 — Content quality + navigation data (2026-08-16)

### Content quality fixes applied

- **Missing h1**: 6 pages had `h1: ""`. Set the top-level `h1` field using the page's own primary heading text:
  - `volvo-angebot-hyra.json` → "Volvo Car Rent" (iframe page, no in-page heading)
  - `volvo-angebot-volvo-bundling.json` → "Volvo Bundling Angebote"
  - `volvo-services-lederreparatur.json` → "Lederreparatur für deinen Volvo"
  - `volvo-services-scheibenreparatur.json` → "Frontscheibenreparatur"
  - `volvo-services-schutzfolien.json` → "Schutzfolien für deinen Volvo"
  - `volvo-ueber-uns-newsletter.json` → "Unser Newsletter"

- **Instagram alt text**: All 55 pages had `instagram_dark.svg` with `alt: "Youtube"`. Fixed to `alt: "Instagram"` (the real site's social icons had a copy-paste bug in the scraper output).

### Observations

- The SCA-001 scraper's `extractImages` uses `cheerio`'s `alt` attribute which faithfully captures the source HTML. The real site has `alt: "Youtube"` on the Instagram icon SVG — this is a real bug in the source content, not a scraper artifact.
- Some page JSONs had pre-existing duplicate keys (e.g., `originalSrc` appeared twice in some sections from the SCA-002 rewrite). These were cleaned up by JSON.parse+JSON.stringify round-tripping. JSON is order-preserving for non-duplicate keys but collapses duplicates (last value wins).
- The `assets-manifest.json` is regenerated by `npm run scrape` (live site). URLs from cision.com and volvocars-news.ch are stable over short periods but the scraper picks up new content regularly.
- The `public/assets/remote/` directory must be included in the commit (it contains binary assets). File sizes: 6.8 KB (YouTube thumbnail) to 7.8 MB (Cision press image).
